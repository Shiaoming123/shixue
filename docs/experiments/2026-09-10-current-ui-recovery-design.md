# 拾学桌面端 UI/UX 修复性重构方案

- 状态：`LOCKED / IMPLEMENTATION COMPLETE / QA PASSED`
- 日期：2026-09-10（Asia/Shanghai）
- 代码基线：`feat/ios-ui-ux-restructure@37b1892`
- 范围：桌面端信息架构、页面密度、导航、列表、日历、设置、编辑器与共享控件；领域命令、数据模型、持久化、重复任务、提醒和学习证据语义不变
- 证据：用户提供的 18 张截图、当前 Web 运行界面、当前源码

## 1. 版本与证据边界

用户截图同时包含拾学界面与 macOS、Codex、飞书、滴答清单等参考界面。参考图只用于提炼结构原则，不照搬品牌外观。

图 6、8、16、17 暴露的问题来自随后已撤回的 `3413883` 方案；当前 HEAD 已回到 `3c31190` 的页面实现。回退消除了部分表面回归，但没有消除共同根因：页面把过多功能永久展开、业务组件自行决定容器、导航语义重复、共享控件没有完整的尺寸与溢出合同。

本轮先冻结桌面代表流程，不直接改生产 UI。上一轮的问题不是“颜色不够像 iOS”，而是先改了材质和组件外观，没有先解决产品结构。

## 2. 总体诊断

当前问题可以归为五个系统性缺口：

1. **层级靠容器堆叠表达。** 页面、快速新增、列表分组、任务行和弹窗都在重复使用圆角、底色、边框和阴影，内容被切成很多互不相关的小块。
2. **导航把领域、视图和用户数据混在一起。** “今天、最近 7 天、完成、清单、学习、用户清单”同时竞争一级入口；清单与分组都使用文件夹语义。
3. **所有能力都常驻首屏。** 日历尤其明显：页面标题、快捷添加、来源管理、未安排、全天事项依次占据纵向空间，时间网格反而成为剩余区域。
4. **浮层没有任务级分类。** 简短选择、完整编辑、设置和危险确认使用相似容器，却各自拥有任意宽高、滚动区和 footer。
5. **组件只统一了外观，没有统一布局责任。** `title` 属性代替真正 tooltip；复合按钮的 DOM 包装会破坏业务 CSS；文本槽、计数槽和 accessory 没有稳定的 flex/grid 约束。

## 3. 新的信息架构

桌面采用“全局领域轨 + 当前领域侧栏 + 主内容”的两级结构。

```text
┌──────┬────────────────────┬─────────────────────────────────────────┐
│ 全局轨 │ 当前领域侧栏          │ 主内容                                    │
│      │                    │                                         │
│ 任务  │ 今天                │ 页面工具栏                                 │
│ 日历  │ 收件箱              │ ─────────────────────────────────────── │
│ 学习  │ 最近 7 天           │ 扁平列表 / 日历网格 / 学习内容               │
│      │ 已完成              │                                         │
│ 搜索  │ 用户清单            │ 可选详情面板                               │
│ 设置  │                    │                                         │
└──────┴────────────────────┴─────────────────────────────────────────┘
```

### 3.1 全局领域轨

- 只保留 **任务、日历、学习** 三个稳定领域；搜索为全局命令，设置固定在底部。
- 图标视觉框为 20px，命中区桌面至少 36px、触控模式至少 44px，全部沿同一中心线对齐。
- Logo 只负责品牌，不再兼任折叠按钮。
- 折叠按钮始终可见、可点击，位置不随 Logo hover 替换；窗口化和中等宽度同样可用。

### 3.2 任务侧栏

- 智能视图依次为：今天、收件箱、最近 7 天、已完成。
- 用户清单在同一“任务”入口内展示；清单管理不是另一个一级页面。
- 单个 `＋` 打开有文字的菜单：
  - **新建清单**：存放任务，可设置图标和颜色。
  - **新建分组**：只整理多个清单，不直接存放任务。
- 分组使用可折叠文件夹；清单使用用户选择的语义图标与颜色点。没有自定义时使用列表图标，不再全部显示相同文件夹。
- 侧栏收起后只保留全局领域轨。用户固定到轨道的清单才显示自定义图标与颜色；其余通过始终可见的展开按钮访问。

### 3.3 响应式结构

| 窗口宽度 | 结构 |
| --- | --- |
| ≥1280px | 56px 全局轨 + 232–248px 领域侧栏 + 主内容；详情可占 340–380px |
| 820–1279px | 56px 全局轨常驻；领域侧栏覆盖式打开，折叠按钮常驻 |
| <820px | 单栏主内容 + 底部领域导航；领域侧栏改为抽屉 |

## 4. 页面与流程重构

### 4.1 任务列表

- 移除“外层大圆角卡片 + 内部硬矩形行”的组合。
- 每个分区使用标题、数量和留白；任务行直接落在内容面上，以缩进分隔线组织。
- 行高：单行 48px；含元信息 60–64px。完成控件、标题、元信息、固定 accessory 各自拥有明确列。
- hover/选中只给当前行 6–8px 的轻背景，不加阴影。
- 标题最多一行，元信息最多一行；完整内容通过详情或 tooltip 获取。
- 行操作默认进入 `⋯`，hover 时可出现最多一个高频快捷动作。

### 4.2 快速新增

- 默认是一条 44px 内联输入，不再套大型卡片。
- 标题输入占主宽；日期、清单、学习模式显示为同高的紧凑 chips；提交按钮与输入垂直居中。
- 仅在用户选择日期或清单时展开对应浮层；提醒、重复、优先级进入“更多选项”。
- 日期与清单控件共享相同的 `field-height` 和基线，不允许一个 44px、一个 36px。

### 4.3 多选

- 进入多选后，页面工具栏切换为批量工具栏，不在列表上方额外插入灰条。
- 左侧显示 `已选择 0 项`，右侧显示可用操作与“退出多选”。零项时动作禁用，但状态文案完整。
- 选中数量变化使用 `aria-live=polite`；批量删除在确认框中显示实际影响数量。

### 4.4 日历

- 日历顶部只保留一条 52–56px 工具栏：今天、前后导航、日期范围、视图切换、筛选、`＋新建`。
- 时间网格是主内容并占满余高。全天区最多两行，超出显示“还有 N 项”。
- 小月历、来源勾选和“未安排 N”进入上下文侧栏；侧栏开合不改变网格高度。
- 未安排任务使用纵向扁平行，保留拖放、建议安排、键盘与手动安排路径。
- 点击空白时间或 `＋新建`，直接在目标时间旁打开轻量日程浮窗；不再经过中转对话框。
- 轻量浮窗只含标题、日期、起止时间、日历来源和保存；“更多选项”无损带入完整编辑器。
- 来源管理使用主从弹窗：左侧来源，右侧选中来源详情；只读外部日程使用详情态。

### 4.5 学习与完成记录

- 学习入口内使用“待复习 / 学习记录 / 节律”分段，避免与任务智能视图竞争一级导航。
- 记录列表使用与任务列表一致的平面行；图标、摘要、日期、固定 chevron 各占一列。
- 长中英文混排不得推动 chevron 或越出容器；展开后再显示证据、阻塞与下一步。

### 4.6 设置

- 桌面设置打开为单例、可缩放的独立设置窗口；默认约 960×680，最小 760×560。
- 左侧分类栏固定约 220–224px，使用浅层背景与一条 1px 分隔线；分类为通用、外观、任务与快速新增、日历、提醒、同步与数据、高级、关于。
- 右侧内容列限制在约 760–820px，随窗口居中，不让设置行无限拉长；只有当前分类滚动，标题栏、关闭和底部必要操作固定。
- 设置项按少量语义分组呈现。每组只保留一层低对比外边框和行间分隔，不给每个设置项单独套卡片、描边或阴影。
- 主题选择改为紧凑色板与名称，不让十余张大卡片占据首屏。
- Web 或紧凑端复用同一内容模型，降级为全屏设置页。

## 5. 统一浮层系统

| 类型 | 用途 | 桌面规格 |
| --- | --- | --- |
| Tooltip | 解释 icon-only 控件 | hover 500ms 或 keyboard focus 显示；离开即消失 |
| Menu/Popover | 筛选、排序、日期、清单、轻量新增 | 280–480px，锚定触发点，自动翻转 |
| Confirm Dialog | 删除、覆盖、系列范围确认 | 420–520px，内容短、后果明确 |
| Editor Dialog | 任务、日程、清单编辑 | 680–820px；固定 header/footer，仅 body 滚动 |
| Workspace Window | 设置、日历来源管理 | 760–1040px，可缩放，主从布局 |

共同规则：

- 任一时刻只有一个模态任务；子选择器优先使用非模态 Popover 或编辑器内部推进。
- Close、Back 与 Cancel 不混用；保存始终可见。
- 桌面只允许正文滚动；header/footer 不跟随滚动消失。
- 所有 icon-only 控件同时具有可访问名称、共享 Tooltip 和可见 focus 样式。原生 `title` 不能作为最终实现。

## 6. 视觉规则

### 6.1 排版

| 角色 | 桌面建议 | 用途 |
| --- | --- | --- |
| 页面标题 | 24–26/32，600 | 当前内容唯一标题 |
| 弹窗标题 | 18–20/26，600 | 明确当前任务 |
| 分区标题 | 13–15/20，600 | 任务组、设置组 |
| 正文/任务标题 | 13–14/19，450–550 | 高频内容 |
| 元信息 | 11–12/16，400 | 日期、清单、状态 |

继续使用现有合法的系统/本地字体栈与 tabular numerals。不要用大面积粗体或极浅灰小字制造层级。

### 6.2 间距与对齐

- 4px 基准；常用间距 4/8/12/16/24/32。
- 页面横向 24–32px；列表行横向 12–16px；弹窗正文 24px。
- 图标、文字、计数和 accessory 使用固定列；所有可缩文字容器必须 `min-width: 0`。
- 同一表单行控件使用同一高度与文字基线。

### 6.3 圆角与阴影

- 行选中 6–8px；控件 8–10px；Popover 12–14px；Dialog/Window 16–20px。
- 内容列表默认无外框、无阴影。只有浮起的 Popover、Dialog、Window 使用阴影。
- 同一视图不同时使用大圆角容器、行圆角、厚描边和阴影表达一层关系。

### 6.4 文本溢出合同

- 列表主列：`minmax(0, 1fr)`；文字槽：`min-width:0; overflow:hidden; text-overflow:ellipsis`。
- chevron、计数、状态图标：`flex:0 0 auto`，不参与文本压缩。
- 单行标题截断；正文允许 `overflow-wrap:anywhere`；中文、英文、数字和代码混排均需覆盖。
- 被截断的可交互行在 hover/focus 时提供完整名称；屏幕阅读器始终读取完整文本。

## 7. 不改变的核心能力

- 任务查询、快速新增解析、筛选、排序、完成、批量命令与撤销。
- 日/周/月/议程、15 分钟吸附、拖动/缩放、键盘替代、全天与截止、冲突、DST/时区。
- 日历来源、外部只读、参与者、重复、提醒、会后结果与系列确认。
- 本地优先存储、CAS/幂等、导入校验、学习完成证据和复习调度。

## 9. 量化验收门槛

- 1440×900 日历可滚动时间网格不少于可用高度 65%，且不少于 520px；1366×768 不少于 420px。
- 日历默认顶部到网格不超过 128px；侧栏/浮窗开合导致的网格高度变化不超过 1px。
- 1024px 工具栏不换行；次要动作进入 More。
- 点击日历空白格到输入标题不超过一次操作；轻量日程浮窗不超过四个主要信息行。
- 所有 icon-only 操作 hover 与 keyboard focus 都显示同名 Tooltip；触控命中区不小于 44px。
- 任意长标题不能越界或推动固定 accessory；200% 缩放时保存、取消、关闭仍可达。
- 所有编辑器只有正文滚动；标题与主操作始终在视口内。
- 每页只有一个主要填充动作；列表内容层不使用阴影。

## 10. 本轮刻意不做

- 不把 macOS、飞书或滴答清单的外观逐像素复制到拾学。
- 不在代表流程获得确认前进入生产代码重构。
