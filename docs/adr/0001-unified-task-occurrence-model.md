# ADR-0001：统一任务核心与重复发生项

- 状态：已接受
- 日期：2026-09-04

## 背景

拾学 v2 以 `StudyTask` 为学习任务核心；下一阶段要成为通用待办应用，同时保留学习证据、专注和复习。Todofy 在 `ff736f53` 中以 `repeat` 字符串保存五种规则，并在完成时直接推进同一任务的截止日和提醒时间。这种实现简单，但无法稳定表达单次跳过、单次修改、历史完成和“仅修改此后发生项”。

## 决策

1. v3 使用统一 `Task`，以可选 `mode: 'general' | 'learning'` 开启学习能力，不维护两套任务表。
2. 组织层级固定为 `ListGroup → TaskList → ListSection`，`Tag` 与清单正交；任务只有一个 `listId`。
3. 一次性任务直接保存计划与截止信息；重复任务由 `RecurrenceSeries` 保存规则，由 `TaskOccurrence` 保存每次独立状态。
4. 重复系列只滚动生成未来窗口：最多未来 90 天且最多 50 个待处理发生项；每次读取/变更后补齐窗口。
5. 完成或跳过只改变当前发生项。编辑提供“本次”“本次及以后”“整个系列”三个明确范围。
6. 计划开始与预计时长形成日历块，截止时间独立保存；把逾期任务加入今天不会覆盖原截止时间。
7. v2 的全部任务迁移为 `mode: 'learning'`，保持任务、事件、会话、完成证据和复习记录的 ID 与关联。
8. “完成后”重复以实际完成瞬间的系列本地日期和墙钟为新基准，再应用 cadence interval，不回到原始锚点网格。周规则先加 `interval` 周，再从该日本地日期向后选择第一个允许的 `weekdays`；月/年规则保留完成日的月日语义并在短月夹到月末。跨 DST 缺口的精确时间采用向前平移缺口的确定性策略（例如不存在的 02:30 变为 03:30）；重叠时间选择第一个匹配瞬间。

## 后果

- 优点：完成历史可追溯；支持专业重复规则、单次例外、日历拖动和未来习惯关联。
- 成本：查询需要把任务定义与发生项投影为列表项；迁移、编辑范围和窗口补齐必须有不变量测试。
- 约束：任何 UI 或未来 Agent 都不得通过改写系列锚点来伪造一次完成。

## 被拒绝的方案

- 完成时推进同一任务日期：会覆盖历史，无法表达单次例外。
- 为学习任务和普通任务建立两套模型：会让搜索、日历、提醒和 Agent 命令重复实现。
- 无限预生成发生项：会造成数据无界增长和规则编辑成本。
